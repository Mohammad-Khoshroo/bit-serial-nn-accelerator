# معماری و پروتکل رابط AXI4

## 1. معرفی: AXI4 چیست؟

**AXI4 (Advanced eXtensible Interface)** یک پروتکل ارتباطی برای تبادل داده بین بلوک‌های IP در FPGA یا SoC است. این پروتکل از نوع **Memory-Mapped** است؛ یعنی Master (در پروژه ما اسکریپت Cocotb نوشته‌شده با Python) داده‌ها را از آدرس‌های مشخص می‌خواند یا در آن‌ها می‌نویسد و Slave (سخت‌افزار Verilog) بر اساس آن آدرس‌ها واکنش نشان می‌دهد.

این پروتکل از **۵ کانال مستقل** تشکیل شده است. هر تراکنش (خواندن یا نوشتن) از ترکیب این کانال‌ها استفاده می‌کند:

1. **Write Address (AW):** «می‌خواهم در این آدرس بنویسم.»
2. **Write Data (W):** «این هم داده‌ای که باید نوشته شود.»
3. **Write Response (B):** «عملیات نوشتن با موفقیت انجام شد.»
4. **Read Address (AR):** «می‌خواهم از این آدرس بخوانم.»
5. **Read Data (R):** «این هم داده‌ای که درخواست کرده بودی.»

تمام سیگنال‌های موجود در این کانال‌ها دارای دو سیگنال **VALID** و **READY** هستند. این دو سیگنال مکانیزم **Handshake** را تشکیل می‌دهند.

داده تنها زمانی منتقل می‌شود که **هر دو سیگنال VALID و READY در یک سیکل کلاک برابر ۱ باشند.**

# 2. جادوی `cocotbext-axi` (چرا سیگنال‌های AXI را در Python نمی‌بینید؟)

در یک تست‌بنچ معمولی Verilog، باید سیگنال‌های AXI را به‌صورت دستی کنترل کنید. برای مثال باید:

* `s00_axi_awvalid` را فعال کنید.
* منتظر شوید تا `s00_axi_awready` فعال شود.
* سپس `s00_axi_wdata` را ارسال کنید.
* و در نهایت پاسخ را از کانال B دریافت کنید.

اما چون در Python از کتابخانه **`cocotbext-axi`** استفاده می‌کنیم، کلاس **`AxiMaster`** تمام پنج کانال AXI و تمام Handshakeها را به‌صورت خودکار در پس‌زمینه مدیریت می‌کند.

به‌عنوان مثال، وقتی دستور زیر را اجرا می‌کنید:

```python
await axi_master.write(0x00, data)
```

کتابخانه به‌صورت خودکار مراحل زیر را انجام می‌دهد:

1. آدرس را از طریق کانال **AW** ارسال می‌کند.
2. داده را از طریق کانال **W** ارسال می‌کند.
3. منتظر پاسخ از کانال **B** می‌ماند.

بنابراین در Python هرگز لازم نیست مستقیماً سیگنال‌های AXI را کنترل کنید. با این حال، برای درک عملکرد سخت‌افزار باید بدانید که Verilog این سیگنال‌ها را چگونه پردازش می‌کند.

# 3. فهرست کامل پورت‌های AXI در Verilog

ماژول `cluster_wrapper.v` سه رابط AXI4 Slave یکسان را در اختیار قرار می‌دهد:

* `s00_axi` (Config)
* `s01_axi` (Input/Weight)
* `s02_axi` (Register Array)

در ادامه، پورت‌های مربوط به **یک رابط** (مثلاً `s00_axi`) آورده شده است. دو رابط دیگر دقیقاً همین ساختار را دارند و تنها پیشوند آن‌ها (`s01_` و `s02_`) متفاوت است.

## سیگنال‌های عمومی (Global Signals)

| سیگنال            | توضیح                                              |
| ----------------- | -------------------------------------------------- |
| `s00_axi_aclk`    | کلاک رابط AXI                                      |
| `s00_axi_aresetn` | سیگنال ریست فعال-پایین (0 = ریست، 1 = عملکرد عادی) |

## کانال Write Address (AW)

| سیگنال                  | توضیح                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------- |
| `s00_axi_awid [11:0]`   | شناسه (ID) تراکنش نوشتن؛ برای حفظ ترتیب تراکنش‌ها استفاده می‌شود.                                             |
| `s00_axi_awaddr [...]`  | آدرس مقصد عملیات نوشتن (مانند `0x40000000 + Offset`).                                                         |
| `s00_axi_awlen [7:0]`   | طول Burst؛ تعداد Beatهای داده (0 = انتقال تکی، 3 = چهار Beat).                                                |
| `s00_axi_awsize [2:0]`  | اندازه هر Beat بر حسب بایت (مثلاً `010` = ۴ بایت = ۳۲ بیت).                                                   |
| `s00_axi_awburst [1:0]` | نوع Burst (`00`=Fixed، `01`=Incrementing، `10`=Wrapping). سخت‌افزار ما از Incrementing (`01`) استفاده می‌کند. |
| `s00_axi_awlock`        | ویژگی استاندارد AXI برای Lock کردن تراکنش (در این طراحی استفاده نمی‌شود).                                     |
| `s00_axi_awcache`       | مشخصات مربوط به سیاست Cache (در این طراحی استفاده نمی‌شود).                                                   |
| `s00_axi_awprot`        | مشخصات سطح حفاظت (Protection Attributes).                                                                     |
| `s00_axi_awqos`         | مشخصات Quality of Service.                                                                                    |
| `s00_axi_awregion`      | مشخص‌کننده Region در AXI.                                                                                     |
| `s00_axi_awvalid`       | Master اعلام می‌کند که آدرس معتبر است.                                                                        |
| `s00_axi_awready`       | Slave اعلام می‌کند آماده دریافت آدرس است.                                                                     |

| سیگنال                 | توضیح                                                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `s00_axi_wdata [31:0]` | داده ۳۲ بیتی برای نوشتن.                                                                                                                         |

| `s00_axi_wlast`        | Master اعلام می‌کند این آخرین Beat در Burst است.                                                                                                 |
| `s00_axi_wvalid`       | Master اعلام می‌کند داده معتبر است.                                                                                                              |
| `s00_axi_wready`       | Slave اعلام می‌کند آماده دریافت داده است.                                                                                                        |

| `s00_axi_bresp [1:0]` | کد پاسخ (`00`=OKAY، `01`=EXOKAY، `10`=SLVERR، `11`=DECERR). در طراحی ما همیشه `00` (OKAY) است. |
| `s00_axi_bvalid`      | Slave اعلام می‌کند پاسخ آماده است.                                                             |
| `s00_axi_bready`      | Master اعلام می‌کند آماده دریافت پاسخ است.                                                     |

# 4. نحوه استفاده سخت‌افزار از این پورت‌ها (به تفکیک هر رابط)

## الف) رابط Config (`s00_axi`) — آدرس پایه: `0x40000000`

**هدف:** کنترل و وضعیت (Control & Status)

ماژول Verilog با نام `Axi4_config_mlp_v1_0_S00_AXI.v` یک حافظه کوچک ۸ بایتی به نام `byte_ram` را پیاده‌سازی می‌کند.

**نحوه استفاده در پروژه:**

* فقط از عملیات‌های خواندن و نوشتن ۳۲ بیتی تک‌انتقالی (Single Beat) استفاده می‌کنیم.
* از Burst استفاده نمی‌شود.

**تعامل از طریق Python**

* `axi_master_config.write(0x00, data)`

  کانال‌های AW و W را ارسال می‌کند. Verilog آدرس را Decode کرده، داده را در `byte_ram` می‌نویسد و سپس پاسخ را از کانال B ارسال می‌کند.

* `axi_master_config.read(0x04, 4)`

  کانال AR را ارسال می‌کند. Verilog داده را از `byte_ram` خوانده و از طریق کانال R به Python برمی‌گرداند.

---

## ب) رابط Input/Weight (`s01_axi`) — آدرس پایه: `0x40001000`

**هدف:** بارگذاری داده‌های ۸ بیتی در BRAMها.

ماژول `Axi4_input_weight_brams_v1_0_S00_AXI.v` دارای حافظه‌ای به اندازه **۱۰۵۶ بایت** است.

**نحوه استفاده در پروژه:**

در هر بار، آرایه‌هایی با اندازه **۳۲ بایت** ارسال می‌کنیم.

کتابخانه `cocotbext-axi` این داده را به‌صورت خودکار به یک **Burst AXI** (با `AWLEN > 0`) تبدیل می‌کند.

**نحوه پردازش در Verilog**

گذرگاه داده AXI دارای عرض **۳۲ بیت** (`s01_axi_wdata`) است، اما حافظه داخلی فقط **۸ بیت** عرض دارد (`byte_ram`).

کد Verilog با استفاده از یک حلقه `for` و سیگنال `WSTRB`، هر کلمه ۳۲ بیتی را به چهار مقدار ۸ بیتی تقسیم کرده و آن‌ها را در چهار آدرس متوالی حافظه می‌نویسد.

**تعامل از طریق Python**

* `axi_master_iwb.write(addr, 32_byte_array)`

  Python یک Burst ارسال می‌کند.

  Verilog هشت Beat داده ۳۲ بیتی (۸ × ۴ = ۳۲ بایت) دریافت کرده و آن‌ها را به ۳۲ خانه ۸ بیتی مجزا در حافظه تبدیل می‌کند.

---

## ج) رابط Register Array (`s02_axi`) — آدرس پایه: `0x40002000`

**هدف:** نگهداری Accumulatorهای ۳۲ بیتی (Bias ورودی و Output خروجی)

ماژول `Axi4_register_array_v1_0_S00_AXI.v` دارای حافظه‌ای به اندازه **۱۲۸ بایت** است.

**نحوه استفاده در پروژه:**

در این رابط داده‌های **۳۲ بیتی** ارسال می‌کنیم.

**نحوه پردازش در Verilog**

برخلاف رابط قبلی، حافظه داخلی نیز ۳۲ بیتی است؛ بنابراین هر داده AXI مستقیماً با یک خانه حافظه متناظر است و نیازی به تقسیم یا بسته‌بندی مجدد بایت‌ها وجود ندارد.

**تعامل از طریق Python**

* `axi_master_ra.write(0x00, bias_data.tobytes())`

  مقادیر Bias به‌صورت داده‌های ۳۲ بیتی ارسال می‌شوند.

* `axi_master_ra.read(0x00, 128)`

  هر ۳۲ رجیستر خروجی را از حافظه می‌خواند.

# 5. ماشین حالت سخت‌افزار (FSM) و سیگنال `logic_wen`

یک سیگنال داخلی مهم در طراحی وجود دارد که باید با آن آشنا باشید:

**`logic_wen`**

هر زمان که ماشین حالت سخت‌افزار (`cluster_ctrl.v`) در حال انجام محاسبات باشد، مقدار این سیگنال برابر **۱** می‌شود.

در AXI Slave مربوط به Config، از این سیگنال برای **جلوگیری از نوشتن تنظیمات جدید توسط Host در زمان اجرای سخت‌افزار** استفاده می‌شود.

علاوه بر این، پس از پایان محاسبات، سخت‌افزار مقدار `done` را تنها در صورتی در `byte_ram[6][0]` می‌نویسد که `logic_wen = 1` باشد.

این مکانیزم از ایجاد **Race Condition** بین نوشتن توسط Host و به‌روزرسانی پرچم `done` توسط سخت‌افزار جلوگیری می‌کند.

# خلاصه برای برنامه‌نویس Python

نیازی نیست نگران سیگنال‌های زیر باشید:

* `VALID`
* `READY`
* `AWLEN`
* `WSTRB`

کتابخانه **`cocotbext-axi`** همه این جزئیات را به‌صورت خودکار مدیریت می‌کند.

تنها کافی است سه مورد زیر را بدانید:

1. **از آدرس پایه صحیح استفاده کنید.**

   * `0x40000000` → Config
   * `0x40001000` → Input/Weight
   * `0x40002000` → Register Array

2. **Offset مناسب را انتخاب کنید.**

   * مانند `0x00` برای داده
   * یا `0x04` برای رجیستر تنظیمات/Done

3. **داده‌ها را با قالب صحیح بسته‌بندی کنید.**

   * استفاده از `NumPy.tobytes()`
   * انتخاب نوع داده مناسب مانند `uint8` یا `int32` پیش از ارسال داده به سخت‌افزار.
